# Спецификация ежедневного чек-листа / Daily Checklist Specification

## Назначение / Purpose

Документ описывает поведение будущего автоматически сбрасываемого чек-листа.
Он не является реализацией. Машиночитаемые начальные данные находятся в
[`checklist-data.json`](checklist-data.json).

## Нормативные настройки

| Поле | Значение по умолчанию | Требование |
|---|---|---|
| `reset.time` | `00:00:00` | Настраиваемое время границы суток |
| `reset.timeZone` | `UTC` | Настраиваемая IANA-зона; общий безопасный default |
| `allianceDuel.timeZone` | `UTC` | Подтверждено [S1] |
| `survivalBattle.timeZone` | `null` | Не подтверждено; интерфейс временно использует общий default с предупреждением |
| `survivalBattle.cycleAnchor` | `null` | Не подтверждено; пользователь или редактор должен задать дату Day 1 |
| `survivalBattle.roundDurationMinutes` | `240` | Подтверждено [S2][S4] |
| `locale.primary` | `ru` | Русский основной |
| `locale.secondary` | `en` | Английский обязательный вторичный |

**Критическое правило:** общий default 00:00 UTC не означает, что Битва за
выживание подтверждённо использует UTC. [S4] указывает только 00:00:00.
Поле её зоны должно оставаться отдельным, видимым и настраиваемым.

## Расчёт суточного ключа

1. Преобразовать текущее время в эффективную IANA-зону события.
2. Вычесть локальное время сброса.
3. Взять календарную дату результата как `cycleKey` в формате `YYYY-MM-DD`.
4. Хранить выполнение по составному ключу
   `{profileId}:{eventId}:{cycleKey}:{taskId}`.
5. При смене `cycleKey` показать новый пустой список; историю не удалять.

Нельзя сбрасывать данные таймером «через 24 часа после открытия»: это даёт
дрейф и ломается после перезапуска. Смена зоны или времени сброса должна
пересчитать отображаемый цикл, но не переписывать историю.

## Дуэль альянсов

- Фаза выбирается по ISO-дню недели в UTC: Monday=1 … Saturday=6.
- В воскресенье показывается набор подготовки `AD-PREP-SUNDAY`, а не
  неподтверждённая седьмая фаза.
- Текущая фаза и оставшееся время должны отображаться всегда.
- Задачи с неподтверждённым переносом, например незабранные задания «Сокол»,
  получают предупреждение и ссылку `VB-AD-006`.

## Битва за выживание

- Шесть окон имеют смещения 0, 240, 480, 720, 960 и 1 200 минут от сброса.
- При заданном `cycleAnchor`:
  `cycleDay = floor(days(resetDate - anchorDate) mod 7) + 1`.
- Пока `cycleAnchor=null`, пользователь вручную выбирает Day 1–7 по экрану
  игры; выбор сохраняется только как наблюдение с датой.
- Пока `timeZone=null`, использовать общий UTC default для отображения, но
  показывать `unverifiedTimeZone=true`.
- Повторы Day 1=Day 3 и Day 2=Day 7 сохраняются как опубликованы; не
  «исправлять» алгоритмом.

## Одновременный независимый зачёт

Задача получает `overlapGroup` только когда одно и то же действие явно есть в
таблицах обоих событий. Интерфейс:

1. показывает две отдельные формулы очков;
2. проверяет активность обеих фаз;
3. не суммирует очки разных событий в общий показатель;
4. не использует слова «множитель» или «бонус двойных очков»;
5. при конфликте обучения солдат показывает +22 и +28 как альтернативные
   неподтверждённые данные, а не вычисляет результат.

## Состояния задачи

| State | Значение |
|---|---|
| `available` | действие уместно сейчас |
| `completed` | пользователь отметил выполнение в текущем цикле |
| `blocked` | нет нужного условия или ресурса |
| `deferred` | намеренно оставлено для будущего окна |
| `unverified` | логика зависит от неподтверждённой механики |

Повторяемые действия должны хранить необязательные `target`, `progress` и
`unit`; бинарные действия используют только состояние.

## Валидация данных

- `id` уникален, ASCII, kebab-case с префиксом события.
- У каждой пользовательской строки есть `label.ru` и `label.en`.
- `sourceIds` ссылаются на [реестр источников](sources.md).
- Любая запись с `confidence != "high"` содержит `verificationIds`.
- Числовые значения не локализуются и не округляются.
- Неизвестное значение хранится как `null`, а не как предполагаемое число.
